# 提示词助手（ComfyUI-PromptLibrary / llm_nodes）

接一个语言模型，把口语化的简短描述扩写成能直接用的提示词。两个节点，共用一份配置：

| 节点 | 分类 | 干什么 | 输出 |
|---|---|---|---|
| **H3 提示词助手** | `提示词工具` | 按 MiniMax H3 官方规范改写**视频**提示词 | 1 个 STRING（整段提示词） |
| **生图提示词助手** | `提示词工具` | 按**预设**改写**生图**提示词 | 2 个 STRING（正向 + 负面） |

你只管写「图里这个女孩站在雨里抬头看天」，它负责补全分镜/镜头/时间戳/声音，或者补全 tag、外貌、服装、光影。

> 这两个节点原本是独立的 `comfyui-h3-prompt-helper` 包，已并入 `ComfyUI-PromptLibrary` 的
> `llm_nodes/` 子目录，跟「提示词库（点击插入）」同属 `提示词工具` 分类。

---

## 一、装在哪

代码在 `ComfyUI/custom_nodes/ComfyUI-PromptLibrary/llm_nodes/` —— 随 PromptLibrary 一起加载，不用单独装。

⚠️ **必须重启 ComfyUI** —— `custom_nodes` 只在启动时扫描一次，运行中放进去的节点不会被加载。
（改了 `web/` 下的前端文件也一样，要么重启，要么浏览器 Ctrl+Shift+R 硬刷新。**生图预设也一样，加完要重启。**）

---

## 二、配置 API（两个节点共用一份）

### 方式一：节点上的「设置 API」按钮（推荐）

右键添加节点 → 点节点上的 **「设置 API」** 按钮 → 填三样：

| 字段 | 填什么 | 例子 |
|---|---|---|
| 接口地址 | OpenAI 兼容的 `/v1` 地址 | `https://api.example.com/v1` |
| 模型 ID | 提供方的模型名 | `gpt-4o-mini` |
| API Key | 你的密钥 | `sk-...` |

面板里的 **「测试连接」** 会真发一个 `ping` 请求，确认地址 / key / 模型都对得上再保存。
按钮文字会跟着变：配置齐了显示 `设置 API · 模型名`，没配齐显示 `⚠ 设置 API（未配置）`。

**两个节点读的是同一份配置** —— 在哪个节点上填都行，另一个自动生效。

### 方式二：直接改文件

`custom_nodes/ComfyUI-PromptLibrary/llm_nodes/config.json`

```json
{
  "base_url": "https://api.example.com/v1",
  "api_key": "sk-...",
  "model": "gpt-4o-mini",
  "temperature": 0.7,
  "timeout": 300
}
```

- `temperature`：0.7 比较合适，想更稳定就调低
- `timeout`：单次请求超时秒数。规范文件较长、模型较慢时可能要调大

两种方式改的是**同一个文件**，互不冲突。

⚠️ **配置存在插件目录，不会写进工作流 json** —— 所以工作流发给别人不会泄 key。
反过来，如果你哪天用 `--listen` 把 ComfyUI 开到公网，记得 `GET /prompt_lib/llm/config` 是**明文返回 key** 的，
那种情况下要先加访问控制。

## 三、H3 提示词助手

### 怎么用

| 输入 | 说明 |
|---|---|
| **描述** | 你想拍的画面，一句话就行。**必填** |
| **模式** | 单图参考 / 多参考混合 / 首尾帧补间，见下表 |
| **时长** | 目标视频秒数（4–15）。**要跟生成节点的 length 对得上** —— 24fps 下 124 帧 ≈ 5.17 秒 |
| **变体** | 改这个数字 = 强制重新生成一次。同一份描述想要第二个版本就把它 +1 |
| **补充要求** | 可选。想额外强调的（"不要出现文字""镜头别切"）写这儿 |

输出是一个 **STRING**，拖线连到 `MiniMaxH3ReferenceToVideo` / `MiniMaxH3ImageToVideo` 的 `prompt` 输入口。

### 三种模式

| 模式 | 吃哪套规范 | 对应工作流 |
|---|---|---|
| **单图参考** | Ref2VA（单张参考图） | ① 单条生成、⑤ TE 加速-单条 |
| **多参考混合** | Ref2VA（多张参考图） | ③ 接力续拍、④ 多参考混合 |
| **首尾帧补间** | FL2VA（首帧 + 尾帧） | ② 首尾帧补间 |

⚠️ 模式选错的话规范就套错了 —— 尤其注意「单图参考」和「首尾帧补间」：
前者是**一张图当参考素材**，后者是**两张图分别当首帧和尾帧**，产出结构完全不同。

### 一个必须知道的限制

**语言模型看不到你的那张参考图。** 它只吃文字。

所以描述里要带一句图里是什么，比如：

> 图里这个黑发女孩，穿蓝色开衫，站在雨里的便利店门口，抬头看招牌

它才能把 `<Subject 1> is the young woman in <Picture 1>, with long dark hair...` 这类引用写对。

## 四、生图提示词助手

### 怎么用

| 输入 | 说明 |
|---|---|
| **描述** | 你想画的画面，一句话就行。**必填** |
| **模式** | 下拉来自预设文件，见下节 |
| **变体** | 改这个数字 = 强制重新生成一次 |
| **补充要求** | 可选 |

两个输出口：

| 输出 | 接到哪 |
|---|---|
| **正向提示词** | 正面 `CLIPTextEncode`（或直接接 `PromptLibraryNode` 之类的中转节点） |
| **负面提示词** | 负面 `CLIPTextEncode`。**预设里 `negative: false` 时这个口返回空串**，接不接都无所谓 |

⚠️ 输出语言由预设决定：英文 tag 式输出英文，中文自然语言式输出中文。你输入端永远写中文。

### 预设：两层结构

**方言层**（稳定的通用写法）和**模型层**（你自己的模型条目）都是数据文件，**全都在包里同一个目录**：

| 层 | 文件 | 内容 |
|---|---|---|
| 方言 | `通用-英文tag式.json`、`通用-中文自然语言式.json` | 两套写法规范，模型条目靠 `extends` 继承它们 |
| 模型 | `noobai-xl.json` / `anima.json` / `krea2.json` / `krea2-edit.json` / `z-image.json` | 每个模型一条，只写差异 |

都在 `<包目录>/image_presets/` 下。下拉里显示的就是这个目录里所有预设的 `name`，按 `order` 排（方言 10/20 在前，模型 100+ 在后）。

**加模型 = 往这个目录丢一个 json + 重启 ComfyUI**，不用碰代码。

预设**只有这一处真源**，没有别的地方要放、也没有覆盖层。

### 加一个新模型

往 `<包目录>/image_presets/` 丢一个 json，然后**重启 ComfyUI**。最小例子：

```json
{
  "id": "my-model",
  "name": "我的新模型",
  "order": 150,
  "extends": "dialect-tag",
  "language": "en",
  "negative": true,
  "negative_fallback": "lowres, bad anatomy, watermark",
  "rules": [
    "这个模型特有的要求，一条一项。"
  ]
}
```

字段表：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 下拉里显示的名字，也是节点「模式」的值。不写就用文件名 |
| `id` | | 唯一标识，被 `extends` 引用时用。不写就用 `name` |
| `order` | | 排前面的小。默认 100，内置是 10 / 20 |
| `extends` | | 继承另一个预设的 `id`：它的 `rules` 会拼在你前面，`language` / `negative` 你没写就跟着它 |
| `language` | | `"en"` 或 `"zh"`，输出语言。不写默认 `en` |
| `negative` | | `true` 时额外输出负面词。不写则继承，都没有就是 `false` |
| `negative_fallback` | | 模型没按两段格式输出时，负面词回落到这份固定词表 |
| `rules` | ✅ | 正向提示词的写法要求，一条一项，会逐条注进 system prompt |
| `negative_rules` | | 负面词的写法要求，一条一项 |

`extends` 是"叠加"不是"覆盖"：模型层只写**差异部分**（比如「质量前缀由工作流里的某某节点负责，你别重复输出」），
通用的写 tag 顺序、数量限制那些留给方言层。链最多 5 层，认不出的 `extends` 只警告、不崩。

### 想分享给别人

预设全在包里，分享包就一起带走 —— 包括你那五个模型条目（别人用不上就当没看见，两条通用的照常能用）。
不想带上自己的模型条目，打包前把对应 json 删掉即可。

## 五、排错

| 现象 | 原因 |
|---|---|
| 节点列表里找不到 | 没重启 ComfyUI |
| 按钮点了没反应 | ComfyUI 启动早于插件安装 → 重启；或看浏览器控制台有没有 404 |
| 「模式」下拉里没有新加的预设 | 预设文件改动只在启动时读一次 → 重启 ComfyUI |
| 下拉里出现了 `（没找到预设文件）` | 两个预设目录都读不到任何 json，看控制台里的警告行 |
| `还没配置 base_url / api_key / model` | 点「设置 API」填一下 |
| `不认识的模式「xxx」` | 那个名字的预设被删了或改名了 → 重启让下拉刷新 |
| `接口返回 HTTP 401/403` | key 不对，或者该 key 没有这个模型的权限 |
| `接口返回 HTTP 404` | 接口地址填错了。注意要写到 `/v1`，**不要**自己加 `/chat/completions`（会自动补） |
| `连不上 ...` | 地址不通 / 网络问题 / 该中转站不支持 chat 接口 |
| 改了配置但没生效 | 改「变体」那个数字强制重跑（ComfyUI 按输入缓存节点结果） |
| 输出的提示词被 ` ``` ` 包住 | 已经自动剥掉了；如果还有残留，说明模型不听话，换个模型 |
| 负面口是空的 | 要么预设写了 `negative: false`，要么模型没按两段格式输出（控制台有警告，负面回落到固定词表） |
| 生成太慢 | H3 的 system prompt 较长（4K–6K tokens），换个更快的模型，或把 `timeout` 调大 |

## 六、目录结构

```
ComfyUI-PromptLibrary/
├── __init__.py                     词库节点 + 汇总 llm_nodes 的注册 + WEB_DIRECTORY
├── data/                           词库 json（PromptLibrary 原本的东西，未改动）
├── web/
│   ├── prompt_library.js           词库抽屉的前端
│   └── prompt_helper.js            两个 LLM 节点上的「设置 API」按钮与面板
└── llm_nodes/                      ← 本文件讲的部分
    ├── __init__.py                 两个节点的注册汇总
    ├── nodes.py                    H3 节点、配置读写、LLM 调用、HTTP 接口
    ├── image_nodes.py              生图节点、预设加载与继承、提示词组装
    ├── config.json                 API 配置（两个节点共用，首次导入自动生成空模板）
    ├── prompts/
    │   ├── base-en.txt             H3 官方规范：T2VA / I2VA / FL2VA / L2VA
    │   └── ref-en.txt              H3 官方规范：全参考模式（Ref2VA）
    ├── image_presets/              预设全在这（方言层 + 模型层）
    │   ├── 通用-英文tag式.json       方言层，通用写法
    │   ├── 通用-中文自然语言式.json
    │   ├── noobai-xl.json          模型层，各只写差异
    │   ├── anima.json
    │   ├── krea2.json
    │   ├── krea2-edit.json
    │   └── z-image.json
    └── README.md                   本文件
```

`prompts/` 下的两份文件是 H3 官方规范原文，**按模式整份注进 system prompt**（不去裁剪，避免漏信息）。
生图那边相反：方言的通用写法写在 json 的 `rules` 里，改起来不用碰代码。
